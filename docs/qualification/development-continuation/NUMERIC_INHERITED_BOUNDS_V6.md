# Inherited numeric bounds — explicit V6

`NUMERIC_BOUND_RESTRICTIONS_V6` extends selected numeric declaration admission
through existing original/inline FilingCollection batches, offline source inspection,
StockWorkspace admission and company-v2 statement consumers. V1–V5 profile order,
defaults and valid legacy artifact values remain unchanged. This is selected numeric
value/restriction validation, not complete schema, OIM, accounting or statement conformance.

Authority: W3C XML Schema Datatypes1.0 Second Edition §§4.3.7–4.3.10. Bounds must
restrict their immediate base value space and cannot widen numeric endpoints or
relax inherited exclusivity. Exact repeated exclusive endpoints have the normative
exception to base enumeration/digit membership, determined against the effective
immediate parent rather than an older ancestor. Existing digit/fixed/enumeration
checks remain. Decimal comparisons are exact and independent of ambient precision.
Empty supported numeric domains reject explicitly. Fixed bound attributes and other
unsupported schema features remain unsupported; no GAAP mapping is inferred.

A new opt-in marker and proof retain effective bounds and an original-DTS/declaration
source fingerprint. Actual collection/product consumers independently validate the
marker, exact metadata types, source URIs/hashes, declared base/derivation/facets,
source fact IDs, normalized/lexical/nil values, context and unit semantic hashes and
references, declaration booleans and expected fact records. Re-signing contradictory
retained values or aspects cannot authorize them. This proves internal source/semantic
consistency; original XML and issuer authentication remain separate source boundaries.

Recovery tests exposed an existing ownership defect: returned coverage referenced
private admitted proof/document dictionaries. Returned coverage is now detached for
all profiles, preserving serialized artifacts while preventing caller mutation of
an admitted collection through its returned financial data.

53 new tests pass, covering original/inline batches, actual company-v2 and offline
CLI consumers, atomic admission, nil/conflicts, bound exceptions, resource limits,
malformed source proofs and re-signed contradictions. Additional legacy numeric/
collection/product and V10 composition checks are retained under
`work/engineering-next/numeric-*.log`. SEC02 remains PARTIAL.
